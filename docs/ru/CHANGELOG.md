# История изменений

Testence в стадии alpha: `0.1.0a1` опубликован на PyPI. Изменения после последнего
опубликованного выпуска собраны в `Unreleased`; совместимость между alpha-версиями не
гарантируется, а несовместимое изменение сопровождается заметкой о переходе
([обновление](upgrading.md)).

## Unreleased

### Добавлено

- `testence mcp`: узкий MCP-сервер (stdio) с семью инструментами цикла «написать и
  доказать»: doctor, snapshot (элементы с готовыми, проверенными на уникальность `Target`),
  click, fill, run, inspect и oracle suggest. Текст страницы маскируется, значения не
  возвращаются, модель нигде не вызывается. См. [MCP](mcp.md). Skill pack 0.1.17.
- `ex.expect_request(...)`: `with ex.expect_request("/api/widgets", method="POST") as sent:`
  привязывает запрос и ответ к блоку, который их вызывает; запрос, который не ушёл, роняет
  блок. `testence auth export` один раз входит и сохраняет сессию (доступ только владельцу)
  для `auth: "storage-state"`.
- `testence agent install --client opencode`: OpenCode читает `.agents/skills`, поэтому
  делит каталог с Codex; если нужны оба, каждый файл пишется один раз.
- `auth: "module:factory"` строит вход из кода проекта (`factory(settings)` возвращает
  `AuthAdapter`), поэтому SSO или подписанный запрос не требуют форка; и
  `auth: "storage-state"` начинает с сохранённой сессии Playwright, а
  `AuthContext.storage_state()` её экспортирует. `doctor --target` не требует
  `TESTENCE_USER` ни для одного из них. Руководство по входу описывает, что делает один
  аккаунт под xdist.
- [Первый тест](first-test.md) (десять минут, без PlanSpec) и [глоссарий](glossary.md),
  в котором, среди прочего, сказано, что `unverified` — не сбой.
- `ex.attach(name, data)` и `allure.attach` сохраняют собственный файл теста (нагрузка,
  лог, картинка) вместе с evidence и отправляют его в экспорты Allure, CTRF и JUnit.
  Текст маскируется, бинарный файл хранится как есть, и его отправляет только `full`.
  Skill pack 0.1.15.
- `ex.route(pattern, status=, json=/body=, abort=)` отвечает на запросы из теста
  (`browser.network_mock`). Каждая подмена записывается (`network.mocked`), а её ответы
  помечаются `mocked`; `save_and_verify_state` и `save_and_verify` не принимают
  подменённый ответ за мутацию. Skill pack 0.1.16.
- `testence_actor(role)`: больше одного пользователя в тесте. Роли из `users` в
  `testence.json` входят со своими учётными данными и получают свои `auth`, `api` и, по
  требованию, `ex` в собственном контексте браузера, изолированном от основной сессии;
  данные каждой роли маскируются. Для проверки прав и «другой пользователь видит мою
  правку». Skill pack 0.1.14.
- `ExpectedState.fields(description, {...})` говорит, что хранимая сущность содержит эти значения, и называет
  каждое отличающееся поле; `OracleFailed` из `verify_state` несёт эту причину.
  Скаффолд `testence init`, пример в поставке и документация используют
  `ex.verify_state` со свежим чтением вместо `urlopen` и `request.node.nodeid`.
  Skill pack 0.1.13.
- `testence oracle suggest <run>` предлагает API-проверку, которую подсказал завершённый
  прогон: для каждой успешной мутации чтение, которое её доказывает (сначала собственный
  трафик приложения), поля для сравнения и вызов `save_and_verify_state`; для удаления —
  `ExpectedState.absent`. Прогон пишет событие `net` на тест (пути с шаблонами и ключи
  тел, значения не записываются). Skill pack 0.1.12: `testence-author` спрашивает прогон
  вместо угадывания endpoints.
- Готовый workflow GitHub Actions ([CI](ci.md), `docs/examples/github-actions.yml`),
  который CI самого репозитория выполняет как есть на проекте `testence init`;
  [руководство по переходу](upgrading.md) с `0.1.0a1`; README показывает настоящий отчёт
  демо ложного зелёного из Quick start.
- `api_auth_from_storage` передаёт same-session API oracle токен, который SPA хранит в
  `localStorage` или `sessionStorage`. На таких приложениях oracle читал как аноним и
  каждая проверка давала `inconclusive` на HTTP 401; теперь эта причина называет
  настройку.
- `ExpectedState.absent(...)` доказывает удаление: 404 без HTML или пустое JSON-значение
  становятся наблюдением, а 401/403, HTML и не-JSON остаются `inconclusive`.
- `testence doctor --target` обращается к `base_url`, проверяет учётные данные и один раз
  пробует войти; перед проверкой браузера `doctor` пишет, что запускает.
- Skill pack 0.1.11: `testence-author` настраивает `api_auth_from_storage` при 401 на SPA
  и доказывает удаление через `ExpectedState.absent`.
- Skill pack 0.1.10: `testence-author` знает, что `ex` уже вошёл, и помечает тесты
  страницы входа или публичных страниц `anonymous=True`.
- `ex.drag(source, destination)` перетаскивает элемент на другой: и HTML5
  drag-and-drop, и элементы на событиях мыши. Падение называет, что нашли и источник,
  и цель. Skill pack 0.1.9 добавляет его в `testence-author`.
- Skill pack 0.1.8: `testence-author` использует `ex.clock.run_for` для таймеров,
  которые сами себя перепланируют, и читает, что нашла цель упавшего шага, прежде чем
  её менять.
- `ex.clock.run_for(ticks)` продвигает поддельное время и запускает все таймеры по пути,
  поэтому обратный отсчёт, планирующий свой следующий шаг, доходит до конца;
  `fast_forward` запускает каждый наступивший таймер один раз.
- `--testence-reruns N` (`TESTENCE_RERUNS`) повторяет упавший тест до N раз без
  дополнительных зависимостей. Каждая попытка записывается отдельной попыткой со своим
  evidence, в том числе под pytest-rerunfailures; прохождение после повтора помечено `flaky` в `inspect`, CTRF (`retries`,
  `flaky`, `retryAttempts`), Allure (retries под одним `historyId`) и свойствах JUnit, а
  `testence ci evaluate --flaky fail` делает его ошибкой ([отчётность](reporting.md#повторы-и-нестабильные-тесты)).
  Раньше все попытки получали один attempt id, а pack первого падения прикреплялся к
  итоговому прохождению.
- `testence export --to junit`: JUnit XML со свойствами идентичности Testence и ID
  кейсов, разделением `<failure>`/`<error>` как в Allure, intent шагов и
  замаскированными файлами evidence ([ADR-0028](adr/0028-junit-exporter.md)).
- `@pytest.mark.testence(tms={"testrail": "C123", "xray": "PROJ-12", ...})`
  объявляет ID кейсов в системах управления тестированием; они попадают в JUnit
  (`test_id`, `test_key`, `testrail_result_step`, `tms.<system>`), метки Allure и
  labels CTRF.
- `evidence.trace` и `evidence.video` (`off`, `on`, `retain-on-failure`) сохраняют trace
  Playwright и видео теста; они перечислены в `test.end` в поле `recordings`, не
  маскируются (`redaction: none`) и попадают только в полный экспорт.
- настройка `emulation`: дескрипторы устройств, локаль, часовой пояс, геолокация (вместе с
  разрешением), permissions, цветовая схема и user agent для каждого контекста, который
  создаёт Testence; записывается в fingerprint прогона, capability `browser.emulation`.
- `with ex.soft("<intent>"):` выполняет все проверки блока и падает один раз в конце
  с `SoftAssertionsFailed` и списком провалившихся; каждая остаётся упавшим шагом с
  пометкой `soft`. Действия и ошибки браузера не смягчаются.
- Вкладки: `ex.switch_page(index)` или `ex.switch_page(url_contains=...)`, который
  ждёт вкладку, открываемую приложением, и `ex.close_page()`.
- Поддельное время: `ex.clock.install`, `fast_forward`, `pause_at`, `resume` и
  `set_fixed_time` поверх clock Playwright, за новой capability `browser.clock`.
- Проверки DSL `expect_value`, `expect_count`, `expect_enabled`, `expect_disabled`,
  `expect_checked`, `expect_attribute` и `expect_url(contains= | equals=)`, шаги
  `press(key, target=None)`, `check`, `uncheck`, `hover` и
  `select(target, label=...)`. Каждый — шаг с intent и evidence; проверки точные.
  Весь словарь — в [Тестировании функции](testing-a-feature.md).
- Skill pack 0.1.7: `testence-author` предпочитает DSL, перечисляет его проверки и действия,
  собирает факты одного экрана в `ex.soft`, ведёт таймеры через `ex.clock` и объясняет,
  когда использовать `ex.native`.
- `with ex.native("<intent>") as page:` передаёт страницу Playwright коду, который DSL не
  выражает, внутри одного записанного шага с событием `native.used`
  ([ADR-0027](adr/0027-native-escape-hatch.md)).
- Evidence: `evidence.redact` в `testence.json` добавляет или исключает имена полей и
  параметров URL, перечисляет переменные окружения, значения которых маскируются, и
  включает маскировку email и телефонов. `evidence.mask` закрашивает перечисленные
  элементы чёрным на каждом скриншоте, включая визуальные эталоны
  ([ADR-0024](adr/0024-evidence-redaction-policy.md)).
- `testence export --attachments full|minimal|none` ограничивает, какие файлы pack
  попадают в экспорт.
- Allure TestOps: `--testence-allure-results DIR` пишет каждый результат сразу по окончании
  теста, побайтно как экспорт после прогона, поэтому `allurectl watch` заполняет запуск в
  реальном времени, а убитый job сохраняет готовые результаты
  ([ADR-0026](adr/0026-streaming-allure-export.md)).
- Allure: идентичности следуют allure-pytest (`export.allure.naming: allure-pytest`), поэтому
  перенесённый набор сохраняет кейсы и историю TestOps; метаданные `@allure.*` читаются без
  установленного allure; `@pytest.mark.testence(allure_id=..., title=..., severity=...,
  labels=..., links=...)` работает без PlanSpec. В карточке — дерево сьютов, читаемые
  замаскированные параметры ([ADR-0025](adr/0025-parameter-display-values.md)), статус
  failed/broken, полный трейс, заголовки сценариев и claims PlanSpec, `categories.json`,
  скриншот падения на упавшем шаге и `evidence.screenshots: always`.

### Безопасность

- Заголовки Bearer и Basic ставились на весь контекст браузера, поэтому токен или пароль
  уходили с каждым запросом страницы на любой origin: CDN, аналитику, хостинг шрифтов.
  Теперь они уходят только на `base_url` и `api_allowed_origins`, как у `ApiClient`;
  авторизация заголовками без них отклоняется.
- Профиль настроек заменял целиком каждую таблицу базового файла, которую повторял,
  поэтому профиль с одним ключом `extra` терял правила `evidence.redact` базы, и
  маскируемые ими секреты попадали в evidence этого профиля открытым текстом. Теперь
  профили сливаются по таблицам.
- Проверка readiness `http` принимала ответ другого хоста, на который её
  перенаправили, а в отчёте называла только настроенный URL. Теперь она завершается
  ошибкой «redirected to another origin».
- На Windows необязательный кэш сессии наследовал ACL каталога: биты режима там ничего
  не ограничивают. Теперь файл ограничивается текущим пользователем до записи сессии, а
  если это невозможно, кэш не сохраняется.
- `report.html` вставлял ledger в блок `<script>` без экранирования `<`, поэтому
  сообщение консоли, URL или текст страницы с `</script>` закрывал блок и исполнялся как
  скрипт при открытии отчёта. Теперь во встроенном JSON экранируются `<`, `>`, `&`,
  U+2028 и U+2029.
- Маскировка evidence сравнивала только точные имена ключей, поэтому `authToken`,
  `sessionToken`, `X-Api-Key`, `csrfToken`, `pwd`, параметры OAuth `code` и `session` в
  URL, JWT и токены провайдеров в свободном тексте, номера карт и секреты, названные в
  данных, как oracle diff `{"field": "authToken", ...}`, могли попасть в ledger, pack и
  загрузку в Allure открытым текстом. Теперь имена сопоставляются по частям, а значения —
  по форме. Export и report повторно применяют записанную политику, поэтому evidence,
  записанное прежним релизом, уходит наружу замаскированным.

### Исправлено

- Вход через форму без сигнала успеха мог принять неверный пароль за вход: поле пароля
  ненадолго исчезает, пока отправка формы заменяет страницу. Теперь вход дожидается
  окончания навигации и проверяет ещё раз.
- Вход через форму с неверным паролем выглядел как голый таймаут Playwright; теперь это
  `LoginFailed` с путём входа, сигналом успеха, который не наступил, и источником
  учётных данных.
- Тест, запросивший только `ex`, работал анонимно, хотя `auth.md` обещал вход до теста;
  теперь `ex` входит по настроенной схеме, а тест страницы входа или публичных страниц
  помечается `@pytest.mark.testence(anonymous=True)`.
- Предложения heal называли поле с подписью по placeholder, обрезали имена до 80
  символов и смотрели только первые 400 элементов, включая скрытые, поэтому
  предложенная цель могла ничего не находить. Теперь кандидаты несут доступное имя,
  которое разрешает role-локатор, а предложение обязано находить ровно один элемент.
- Пример oracle в `auth.md` вызывал `verify` с четырьмя аргументами и падал с
  `TypeError`; теперь набор тестов компилирует каждый Python-сниппет документации.
  `testence.adapters.AuthAdapter` — это протокол `testence.auth` (ADR-0010), а не
  второй, противоречащий ему.

- Декораторы `@allure.*` работают без allure-pytest. Пакет `allure` создаёт метки только
  через слушателя, которого регистрирует allure-pytest, поэтому набор, отказавшийся от
  allure-pytest, молча терял все метки, ссылки, id и заголовки; теперь Testence
  регистрирует того же слушателя (дополнение к ADR-0013). Вызовы `allure.dynamic.*`
  попадают в результат Allure своей попытки, а severity из Enum экспортируется как
  `critical`, а не `Severity.CRITICAL`.
- `--testence-reruns` сохраняет фикстуры модуля, класса и сессии вокруг повторяемого
  теста: упавший последний тест модуля или прогона сносил их, и повтор создавал их
  заново. Строгий XPASS больше не повторяется. На pytest 8.0 метод теста при повторе
  получает новый экземпляр.

- Значения `.env` сохраняли хвостовой `# комментарий`, и `PASSWORD=s3cret  # rotate`
  входил с комментарием в составе пароля. Теперь значение без кавычек заканчивается на
  пробеле перед `#`, а значение в кавычках берётся как есть.
- `expect_screenshot` без записанного эталона падал с `FileNotFoundError` операционной
  системы; теперь проверка inconclusive и объясняет, как записать эталон.
- Повтор получал тот же seed marker, что и повторяемая попытка.
- Вторая сессия pytest в одном процессе (встраивание, вызывающее `pytest.main` дважды)
  наследовала run id первой и записывала запуск, хотя Testence не использовала.
- Запуск xdist, у которого все воркеры упали до записи своих shard, не оставлял ledger
  вовсе.
- Неверная настройка в `testence.json` или окружении останавливала любую сессию pytest
  трассировкой `INTERNALERROR`. Теперь в сессии Testence это одна строка ошибки
  использования, а сессию без Testence она не затрагивает.
- `testence inspect`, `report`, `metrics` и `export` на пути, который не является
  запуском, падали с трассировкой, а `inspect` и `export` выдавали пустой запуск за
  результат. Теперь они завершаются с кодом 2 и сообщают, что путь — не запуск.
  Человекочитаемый `inspect` печатает путь к pack каждого упавшего теста.
- Возврат на вкладку заново навешивал слушатели сети, консоли и websocket, и каждое
  следующее событие вкладки записывалось столько раз, сколько раз на неё переключались.
- Клиентский `navigate()` считал `http://localhost:30001` тем же origin, что
  `http://localhost:3000`, а `/apple` — путём внутри `/app`.
- `wait_for_count(target, minimum=0)` ждал один элемент и падал по таймауту.
- `run.end` не считал случаи `not_run`, и записанное после `-x` или `--maxfail` событие
  не сходилось с числом собранных тестов.
- Oracle diff считал `True` и `1` равными и сравнивал вложенный текст вместе с
  окружающими пробелами.
- pytest, запущенный подпроцессом из теста внутри воркера xdist, наследовал
  `PYTEST_XDIST_WORKER` и писал шард воркера без ledger контроллера, поэтому прогон
  не завершался. Номер воркера теперь берётся у самого xdist.
- `expect_hidden` по таймауту поднимал `TimeoutError` Playwright, и элемент,
  который так и не исчез, попадал в отчёт как `broken`. Теперь это
  `AssertionError`.
- `expect_text` поднимал `TimeoutError` Playwright, когда текст так и не появлялся, и
  расхождение с продуктом выглядело как сбой окружения (`broken`). Теперь он поднимает
  `AssertionError`, как уже делал `expect_visible`.
- Quality packs: пак с путями, различающимися только регистром или Unicode-нормализацией,
  например `quality/A.json` и `quality/a.json`, принимался. Файловые системы macOS и
  Windows по умолчанию хранят их как один файл: на диск попадал один файл, а lock учитывал
  два, или пак, собранный на Linux, падал с невнятным несовпадением дайджеста. Теперь
  такой пак отвергается с указанием пары путей.
- Evidence: перехват сети с более чем одним запросом очищался только текстовыми
  правилами, поэтому поле с паролем в теле запроса могло попасть в `network.jsonl`
  открытым текстом. JSON Lines теперь очищаются построчно.
- Жизненный цикл: неудачный старт браузера оставлял процесс драйвера Playwright
  запущенным, по одному на каждый упавший прогон. `start()` освобождает созданное.
- Quality packs: если файловая система отказывала в блокировке операции, как бывает на
  томах SMB и NFS, команда сообщала «another quality pack operation is in progress».
  Теперь так сообщается только о реальной конкуренции; прочие сбои блокировки называют
  файл замка, системную ошибку и сетевую файловую систему как вероятную причину.
- `switch_page()` не переустанавливал перехватчики, из-за чего для второй вкладки
  разделы сети и консоли в evidence pack оставались пустыми.
- `TESTENCE_DEBUG_PORT=0` показывал `127.0.0.1:0` в манифесте триажа. Движок резолвит
  реальный свободный порт, и к браузеру с местом падения снова можно подключиться.
- `.env`, `testence.json` и `testence.toml` читаются как UTF-8 с необязательной меткой
  порядка байтов: файл, сохранённый редактором Windows, больше не теряет первый ключ.
- Битый файл настроек сообщает имя файла и позицию вместо трассировки, а относительная
  навигация без `base_url` называет недостающую настройку.
- Пустой `TESTENCE_BROWSER_CHANNEL` сохраняет умолчание пакета вместо запуска без канала.
- Умолчательный селектор кнопки отправки формы логина находит и `<button>` без явного
  `type`, который по спецификации HTML отправляет форму.
- Файл `.DS_Store` или AppleDouble `._name`, который Finder оставляет в открытой папке,
  больше не блокирует восстановление quality pack, не меняет идентичность доставки
  каталога Allure в CI и не попадает в установленный skill pack из editable checkout.
  `Thumbs.db` и `desktop.ini` от Проводника пропускаются так же.
- Expected state: чтение, которое планировщик ОС задержал за дедлайн, могло закрыть
  положительное окно `stability_ms`, и окно длиннее дедлайна проходило, хотя его никто
  не наблюдал. Положительное окно теперь должно уложиться в дедлайн; точечная проверка
  с `stability_ms=0` не меняется.
- Демо-сервер, который `testence demo run` записывает в проект, тестовые фикстуры и
  серверы бенчмарков больше не резолвят `127.0.0.1` обратно в имя хоста при `bind`. На
  macOS-раннере первый такой запрос в процессе занимал 35 с: каждый сценарий демо
  стартовал на 35 с позже, а цели `bench/competitive` и `bench/i3_baseline` не успевали
  открыть порт за отведённое ожидание. Сервер даёт новый модуль `testence.loopback`,
  статику раздаёт `python -m testence.loopback PORT`.
- Expected state: два совпавших чтения на краях окна стабильности, между которыми
  планировщик спал, закрывали окно. Теперь положительному окну нужно и чтение внутри.
  Окно не короче дедлайна, отрицательный дедлайн и неположительный интервал опроса дают
  `ValueError`, и `save_and_verify_state` проверяет их до клика по сохранению, а не
  после отправки мутации.

### Изменено

- Человекочитаемый `testence inspect` начинает с результата исполнения
  (`2 passed, 1 failed`), затем показывает assurance; он также перечисляет нестабильные
  тесты и pack каждой упавшей попытки.
- Debug port браузера выбирает операционная система, если `debug_port` не задан.
  Фиксированный 9222 был общим на машину: второй запуск на том же хосте получал
  браузер, у которого не поднимался devtools-сервер, и запуск мог висеть до таймаута.
- Сессия pytest пишет каталог запуска только если это сессия Testence: её запустил CLI
  `testence`, ей передана опция `--testence-*` или в ней собран тест с фикстурой или
  маркером Testence ([конфигурация](configuration.md#когда-сессия-pytest-записывает-запуск)).
  Установка пакета больше не заставляет посторонний набор писать `runs/`.
- Упавший шаг с целью сообщает, что нашла цель: текст единственного совпадения, число
  совпадений и тексты первых, а без совпадений — записи дерева доступности с тем же
  именем.
- CTRF: шаги, вложения, путь сьюта, labels, параметры и трейс пишутся в штатные поля
  CTRF; `extra.steps` (список строк intent с отступами) заменён на `steps`.
  `summary.start`/`stop` присутствуют всегда, как требует схема.
- Test plan Allure: запись без совпавшего теста попадает в отчёт (предупреждение, событие
  `testplan.unresolved`, экспорт, квитанция CI), а остальной план выполняется;
  `--testence-testplan-unresolved=fail` возвращает строгое поведение. `allure_id` на
  параметризованном тесте выбирает все варианты, `fullName` в стиле allure-pytest — тоже,
  перекрывающиеся записи выбирают тест один раз, неизвестные поля плана игнорируются с
  предупреждением. План, в котором ничего не нашлось, по-прежнему падает.
- Экспорт Allure: `fullName`, `testCaseId` и `historyId` следуют allure-pytest для тестов без
  явного кейса PlanSpec (`export.allure.naming: nodeid` возвращает поведение 0.1.0a1);
  тегами становятся только пользовательские маркеры без аргументов; параметры показывают
  замаскированные значения (`export.allure.parameters: digest` возвращает digest);
  ошибка в теле теста, не являющаяся ассертом, — `broken`.

- CI гоняет тестовую матрицу, smoke установленного wheel и визуальную симуляцию
  клиентов на macOS (Apple Silicon). `0.1.0a1` опубликован без macOS-квитанций.
- `testence init` записывает readiness-маппинг для сгенерированного плана, поэтому
  `plan prepare` в только что инициализированном проекте отвечает `ready`.
- `testence doctor` запускает настроенный канал браузера вместо проверки пути к
  bundled-исполняемому файлу и сообщает команду, которая чинит ошибку. Проверка
  называется `browser`.
- `testence --version` печатает установленную версию.
- Ссылки в README абсолютные и работают на PyPI, а quick start идёт по пути
  `pip install testence`, которому не нужен клон репозитория.
- CI запускает и линтит `examples/`, на который ссылается опубликованный quick start.

- `TESTENCE_BROWSER_CHANNEL` теперь задаёт канал и для `Settings` и движков, создаваемых
  напрямую, минуя `Settings.load`: машина, на которой не стартует bundled Chromium,
  может гонять браузерные тесты на `msedge` или `chromium-headless-shell`; явные
  аргументы и умолчания CI не меняются.

### Добавлено

- Детерминированное исполнение Playwright-over-CDP за протоколом engine.
- Pytest DSL с намерением, exact-by-default assertions и fingerprints элементов.
- Append-only evidence ledger `testence/1`, ограниченные evidence packs и
  single-file HTML report.
- Расширяемые стратегии аутентификации и API client с общей browser session для
  UI-to-API oracles.
- Проверяемые предложения locator healing; упавший шаг никогда не получает silent
  rebind.
- Process-sharded evidence для необязательного `pytest-xdist`.
- Экспортёры Allure и CTRF, рендерящиеся из ledger.
- Синтетические mutation corpora для проверки false green, false red и качества healing.
- Reference compute kernels за версионированным optional-native ABI.
- Версионированные контракты PlanSpec и verdict с трассировкой claims через pytest,
  ledger, evidence packs и отчёты.
- Версионированный набор Agent Skills для `plan`, `author`, `triage` и `repair` с
  метаданными Codex и безопасным контрактом cross-client обновления.
- Профиль production-built React и multi-process performance-budget gate для navigation,
  controlled inputs и mutation synchronization.
- Отдельный shared-browser CDP профиль и budget для повторных agent-authoring runs.
- Opt-in warm modes для `bench` и `watch`, переиспользующие Python и pytest с reload
  проектных модулей между изолированными sessions.

### Изменено

- Text assertions по умолчанию используют exact matching; containment задаётся явно.
- Evidence metrics считают latency листовых шагов и не дублируют вложенные actions.
- Метрики interaction flake используют identity теста и digest кода.
- Network capture записывает aborted requests как first-class evidence.
- SPA readiness распознаёт non-text controls внутри асинхронно mounted roots вместо
  пятисекундного ожидания только `innerText`.
- Signalled save oracles синхронизируются по scoped mutation response вместо глобального
  `networkidle`; fingerprint capture использует один non-waiting browser evaluation.
- Form fill получил opt-in `fast=True`, сохраняющий input events и пропускающий уже
  доказанные предыдущим readiness gate actionability checks.
- Network capture waits отдают управление event loop квантами по 10 ms; на поддерживаемом
  real-React профиле p95 наблюдения быстрого POST response снизился с 63 до 16 ms.
- CDP-attached runs больше не закрывают context launcher'а. На поддерживаемом профиле
  p50 fresh run снизился с 3,21 s при launch-per-run до 2,02 s с shared browser.
- Warm pytest sessions на каждой итерации сбрасывают run ids, fixtures, auth и evidence
  writers, сохраняя одно Playwright/CDP engine connection. На поддерживаемом
  React-профиле p50 bootstrap снизился с 2,81 до 0,45 s, а p50 всего run — с 3,45 до
  1,13 s.

### Безопасность и гигиена релиза

- До инициализации репозитория удалены локальные credentials, browser profiles,
  сгенерированные run data и application-specific черновые материалы.
- Публичные примеры используют только зарезервированные example domains и синтетические
  приложения.

## Примечания к benchmark

Сохранённые файлы результатов E1, I3 и kernels — воспроизводимые snapshots, а не
продуктовые заявления. Hardware, browser, runtime и target latency существенно влияют
на числа; новые релизы должны публиковать точную команду и окружение вместе с любым
результатом.
React gate запускается командой `python bench/react_latency.py --repeats 5 --check`;
его широкие ceilings ловят timeout-shaped регрессии, но не являются cross-host speed claim.
