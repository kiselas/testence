# MCP-сервер

`testence mcp` даёт агенту вызовы, нужные циклу «написать и доказать», по Model Context
Protocol (stdio). Он узкий намеренно: цикл агента, а не весь фреймворк. Ничто в нём не
вызывает модель, а тесты, которые пишет агент, в CI по-прежнему идут без неё
([ADR-0006](adr/0006-no-llm-in-runner.md)).

## Подключение клиента

Запускайте из проекта (каталог с `testence.json`):

Claude Code, `.mcp.json`:

```json
{"mcpServers": {"testence": {"command": "testence", "args": ["mcp", "--project", "."]}}}
```

Codex, `~/.codex/config.toml`:

```toml
[mcp_servers.testence]
command = "testence"
args = ["mcp", "--project", "."]
```

OpenCode, `opencode.json`:

```json
{"mcp": {"testence": {"type": "local", "command": ["testence", "mcp", "--project", "."], "enabled": true}}}
```

Это формат каждого клиента; если ваша версия отличается, смотрите документацию MCP
клиента. `--headed` показывает браузер исследования.

## Семь инструментов

| инструмент | что делает |
|---|---|
| `testence_doctor` | проверяет среду; `target: true` ещё обращается к `base_url`, проверяет учётные данные и пробует войти |
| `testence_snapshot` | открывает страницу (`url`, путь на `base_url` или абсолютный) и перечисляет интерактивные элементы; у каждого есть `Target`, который его адресует, Python, который его записывает, и число совпавших элементов: `unique: true` можно использовать как есть |
| `testence_click` | нажимает `Target` в браузере исследования, чтобы увидеть результат до записи шага |
| `testence_fill` | заполняет поле; значение в ответ не возвращается |
| `testence_run` | запускает pytest через `testence run` и возвращает код выхода, каталог запуска и его сводку |
| `testence_inspect` | итог запуска: счётчики выполнения и assurance, ошибки целостности, evidence packs, нестабильные тесты |
| `testence_oracle_suggest` | API-проверки, которые подсказал завершённый запуск ([тестирование фичи](testing-a-feature.md)) |

Сеанс из нескольких вызовов: снимок страницы, click и fill, чтобы понять поток, обычный
pytest-файл с `ex`, запуск, разбор, затем подсказки oracle и API-проверка.

## Чего он не делает

- Нет инструмента записи файлов: изменения кода остаются обычными правками под правами
  самого клиента.
- Текст страницы маскируется политикой проекта до того, как его увидит агент
  ([конфигурация](configuration.md#политика-сбора-evidence)); введённое значение не
  возвращается; `run_dir` должен лежать внутри проекта.
- Браузер исследования отделён от браузеров запуска и входит под `auth` проекта.
  `testence_run` запускает собственные тесты проекта, то есть исполняет код по замыслу:
  давайте его только клиенту, которому доверили бы запуск `pytest`.
- Пока не покрыто: исправление по предложению, отправка verdict и инструменты PlanSpec
  остаются в CLI ([процесс агента](agent-workflow.md)).
