# Переход с 0.1.0a1

Что меняется для набора, написанного под опубликованный `0.1.0a1`, и как вернуть прежнее
поведение, где это возможно. Полный список — в [истории изменений](CHANGELOG.md).

## Поведение, которое вы можете заметить

| Изменение | Что сделать |
|---|---|
| `ex` входит по настроенной схеме `auth`; раньше входил только тест, запросивший ещё `testence_api` или `testence_auth` | тест страницы входа или публичных страниц: `@pytest.mark.testence(anonymous=True)` |
| Заголовки Bearer и Basic уходят только на `base_url` и `api_allowed_origins`; авторизация заголовками без них отклоняется | перечислите в `api_allowed_origins` каждый origin, который должен их получать |
| Сессия pytest пишет `runs/`, только если это сессия Testence (CLI, опция `--testence-*` или тест с фикстурой или маркером Testence) | ничего; чтобы записать весь набор, запускайте через `testence run` или передайте опцию `--testence-*` |
| Порт отладки браузера выбирает операционная система | задайте `debug_port`, если к браузеру нужно подключаться по известному порту |
| Неудачный вход через форму — `LoginFailed` с путём и отсутствующим сигналом успеха, а не таймаут Playwright | ловите `testence.auth.LoginFailed`, если ловили таймаут |
| Отсутствующий визуальный эталон — `unavailable` (inconclusive), а не ошибка файловой системы | создайте эталон, как раньше |
| Профиль настроек сливает таблицы с базовым файлом, а не заменяет их | пустая таблица (`{}`) в профиле больше не очищает таблицу базы; перечислите ключи, которые нужно изменить |
| Представления oracle сравнивают булевы значения строго (`True` — не `1`) | сравнивайте значение, которое возвращает API |

## Отчёты и экспорт

| Изменение | Прежнее поведение |
|---|---|
| `fullName`, `testCaseId`, `historyId` в Allure следуют allure-pytest для тестов без кейса PlanSpec | `export.allure.naming: nodeid` |
| Параметры показываются замаскированными значениями | `export.allure.parameters: digest` |
| В теги попадают только пользовательские маркеры без аргументов | — (исправление) |
| Ошибка не-ассерт в теле теста — `broken` | — (исправление) |
| Запись test plan Allure, не нашедшая тест, — предупреждение, остальное выполняется | `--testence-testplan-unresolved=fail` |
| Шаги, вложения, метки и параметры CTRF используют собственные поля CTRF; `extra.steps` заменён на `steps` | — |
| Декораторы `@allure.*` и `allure.dynamic.*` работают без allure-pytest | — (исправление) |

## Python API

- `testence.adapters.AuthAdapter` — это протокол `testence.auth.AuthAdapter`
  (`authenticate(engine) -> AuthContext`, ADR-0010). Прежняя форма `login(engine) -> None`
  внутри Testence не вызывалась.
- Новые методы протокола Engine (`hover`, `drag`, `set_checked` и другие) для сторонних
  движков необязательны: DSL поднимает `UnsupportedCapability` с именем отсутствующего.
  `api_auth_from_storage` требует `storage_item`.
- Новое: `ExpectedState.absent(...)`, `api_auth_from_storage`, `--testence-reruns`,
  `testence doctor --target`.

Навыки агента в проекте — это копии: после обновления `testence agent verify --project .
--client <client>` сообщает `drift`, пока `testence agent install` не приведёт их к
поставляемому набору.
