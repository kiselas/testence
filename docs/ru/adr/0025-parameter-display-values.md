# ADR-0025: Замаскированные отображаемые значения параметров в ledger

Статус: accepted.

## Контекст

ADR-0019 хранил только SHA-256 digest параметров теста, чтобы значение секретного
параметра не попадало в evidence. Каждый экспортированный параметр Allure выглядел как
`sha256:...`: пользователь TestOps не видел, какая роль, браузер или сумма упали, а
перенесённый с allure-pytest набор терял читаемые значения.

## Рассмотренные варианты

- **Только digest.** Безопасно, но нечитаемо.
- **Исходные значения.** Читаемо, но параметр-пароль попадает в общий TestOps.
- **Замаскированные отображаемые значения.** Представление значения как у allure-pytest,
  пропущенное через политику маскировки evidence (ADR-0024) как запись name/value:
  параметр с именем секрета маскируется, значения секретной формы удаляются.

## Решение

`test.start.allure.parameters` хранит отображаемые значения `{name, value}`, вычисленные,
пока значения существуют; идентичностью остаются digest (`parameters`, `variant_id`).
Allure exporter показывает отображаемые значения и помечает замаскированные
`mode: "masked"`. `export.allure.parameters: digest` возвращает вывод только digest.
Значения, которые pytest вставляет в id теста, этой маскировкой не покрываются; плагин
предупреждает, если значение параметра с именем секрета оказалось в id.

## Последствия

Значения параметров появляются в evidence и экспорте, если политика их не маскирует.
Хеши для `historyId` allure-pytest считаются из исходных значений при сборе тестов, как
делает allure-pytest, и хранится только хеш.

## Tripwire

Значение параметра с именем секрета в любом экспортированном файле или сообщение о
секретном значении в карточке, которое политика должна была поймать, открывает решение
заново.
