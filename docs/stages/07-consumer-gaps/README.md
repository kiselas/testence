# Этап 7. Пробелы, которые закрывает первый боевой потребитель

Версия плана: **1.0, 9 ноября 2026**.
Исходная точка: `main` на `3938a0b` (0.1.0a3 опубликован 05.11.2026).
Статус: **в работе**.
Связь: продолжает [этап 6](../06-agent-loop-release/README.md).

## 1. Откуда взялся план

У Testence появился первый набор, который гоняется каждый день: около 270 UI-тестов
внутреннего продукта на Koobiq и react-aria, девять экранов, шесть стендов, параллель
на общем стенде. Его обвязка показывает, чего движку не хватает, лучше любого аудита:
всё, что набор написал сам, движок должен был дать.

| Что сделал набор сам | Сколько | Чем это плохо |
|---|---|---|
| `ex.native`, чтобы прочитать текст, опции, строки, атрибут | около 40 вызовов | шаг без цели и проверки; страница после него не передаётся следующему тесту (`page_reuse: module` выключен у всего набора) |
| `ex.native` для геометрии: рамка панели, заголовки, границы столбцов | около 15 | то же; плюс свой цикл `requestAnimationFrame` |
| `ex.native` для действий: двойной клик, тяга на смещение, HTML5 drag с ручкой, размер окна, перезагрузка, запись в storage, вторая вкладка | около 30 | свой JS на каждый случай, фиксированные паузы между событиями |
| фиксированные паузы внутри шагов | 25 | ждут время, а не состояние |
| ручное снятие зависшего воркера xdist | 1 раз за неделю | восемь минут без событий, затем ручной kill и `broken` у соседей |
| своя таблица «на какой сборке шёл прогон» | — | прогон этого не знает; общий стенд пересобирают посреди прогона |
| номера ручных кейсов в докстрингах | все тесты | машинной связи «кейс → тест → итог» нет, покрытие считается руками |
| свои помощники вместо кита: диалог без заголовка Koobiq, обязательный select, react-select без подписи | 4 модуля | кит не закрывает частые формы продукта |
| свой скрипт времени прогона, свой шаблон GitLab CI, свой справочник на 400 строк | 3 | каждый следующий потребитель напишет их заново |

## 2. Решения

1. **Что набор делал через `ex.native`, становится шагом DSL.** Шаг с целью пишет
   намерение, длительность, отпечаток и описание совпадений при падении. Чтение не делает
   страницу «грязной»: `page_reuse: module` её передаёт.
2. **Чтение возвращает значение тесту и не пишет его в журнал**, как `input_value`:
   в прочитанном тексте может быть секрет. В журнал идёт только размер.
3. **Сторож теста не повторяет и не убивает процесс pytest.** Тест, превысивший срок,
   падает со стеком места, где висел, и с паком; воркер продолжает. Ретраев нет.
4. **Паспорт цели читается один раз в начале и один раз в конце прогона.** Расхождение
   значит, что цель пересобрали посреди прогона; это видно в `inspect`, отчёте и сводке CI.
5. **Связь с ручными кейсами — через существующий `tms`**, без новой сущности плана.
   PlanSpec остаётся строгим путём; кейсы — путь команд, у которых план живёт в файлах кейсов.
6. **Кит не угадывает.** Где компонент продукта не даёт однозначного адреса, кит
   принимает явный параметр и говорит в ошибке, какой.
7. Ни один пункт не ослабляет гейты и не добавляет ретраи (AGENTS.md, CONTRIBUTING).

## 4. Пункты

### T01. Читалки

| Шаг | Возвращает | Ждёт |
|---|---|---|
| `ex.text(target)` | видимый текст одного элемента | элемента, как `click` |
| `ex.texts(target, minimum=1)` | тексты всех совпадений | `minimum` совпадений; `minimum=0` — не ждёт |
| `ex.count(target)` | число совпадений сейчас | нет (проба отрисовки, как у `expect_hidden`) |
| `ex.is_visible(target)` | виден ли сейчас | нет |
| `ex.attribute(target, name)` | значение или `None` | элемента |
| `ex.box(target)` / `ex.boxes(target)` | `Box(x, y, width, height)` | видимого элемента; `settled=True` — ещё и остановки |
| `ex.url()` | адрес страницы | нет |
| `ex.storage_item(key, session=False)` | значение или `None` | нет |
| `ex.read_js(intent, function, arg)` | результат функции страницы | нет |

`read_js` — чтение, а не `native`: страница передаётся дальше, но правило «функция
только читает» на совести автора, и документация это говорит.

**Приёмка.** Тест на каждую читалку на локальной странице; значение не попадает в
`run.jsonl`; падение строгого `text` на двух совпадениях называет оба; страница после
читалок передаётся при `page_reuse: module`.

### T02. Действия

- `ex.double_click`, `ex.right_click`, `ex.click(..., modifiers=["Control"])`.
- `ex.drag_by(target, dx, dy=0, steps=8)` — нажать в центре, сдвинуть, отпустить:
  край панели, граница столбца, ползунок.
- `ex.drag(source, destination, html5=True, handle=None)` — события HTML5 с одним
  `DataTransfer`, по кадру между событиями: строка вне окна и `draggable` только после
  `mousedown` на ручке.
- `ex.type(target, text)` — клавиатурой, с позиции курсора (редакторы, маски).
- `ex.set_viewport(width, height)`, `ex.reload()`, `ex.set_storage({...}, session=False)`.
- `ex.new_page(url)` — вкладка того же контекста (второй клиент той же учётки), сразу
  текущая; назад — `ex.switch_page(0)` или `ex.close_page()`.

Окно другого размера и новая вкладка — состояние теста: страница с ними не передаётся.

**Приёмка.** Тест на каждое действие; паузы внутри — кадры, а не миллисекунды.

### T03. Сторож теста

`--testence-test-timeout S`, `TESTENCE_TEST_TIMEOUT`, `test_timeout_s` в `testence.json`,
`@pytest.mark.testence(timeout_s=…)` на тест. Срок покрывает setup, call и teardown.

По истечении:

1. в журнал — `test.deadline` со стеком главного потока в момент срока;
2. в тест — исключение `TestDeadlineExceeded` (асинхронно, в главный поток);
3. если поток висит в вызове драйвера и исключение не дошло за 5 с, сторож убивает
   дерево процессов движков этого теста (как T09 этапа 6); вызов возвращается, тест
   падает тем же исключением.

Подключённый чужой браузер не убивается. Браузер воркера после этого поднимается заново.

**Приёмка.** Тест, висящий в Python, падает за срок + 1 с; тест, висящий в вызове
драйвера, — за срок + 6 с; следующий тест того же процесса зелёный; пак и стек на месте.

### T04. Паспорт цели

```json
"target_info": {"path": "/api/v1/info", "auth": false, "fields": {"backend": "/0/git/commit"}}
```

Один GET в начале прогона и один в конце (контроллер xdist или единственный процесс).
`fields` — JSON Pointer; без `fields` берётся весь ответ, обрезанный до 4 000 знаков и
замаскированный. События `target.info` (`phase: start|end`); расхождение — `changed: true`.
Видно в `inspect`, отчёте HTML, окружении Allure, свойствах JUnit и `ci summary`.
Недоступный адрес — предупреждение, прогон не падает.

### T05. Кейсы

`@pytest.mark.testence(tms={"cases": ["SHOP-12/3"]})` уже экспортируется. Добавляется:

- `"cases": {"paths": ["cases/*.md"], "key": "^[A-Z][A-Z0-9]*-\\d+"}` в `testence.json`:
  где лежат файлы кейсов (формат `plan skeleton`) и как из имени файла получить ключ;
  id кейса — `<ключ>/<номер>`;
- `testence cases [RUN_DIR] [--json] [--markdown]`: каждый кейс файлов — тест, итог и
  паспорт цели; сводка автоматизированных по файлу; id в маркере, которого нет в файлах, —
  ошибка (код 3). Без `RUN_DIR` — по сбору pytest, без запуска.

### T06. Киты

- `koobiq.dialog(ex, title, header=...)`: диалог, у которого продукт рисует заголовок
  своей разметкой (абзац, заголовок); `exact=False` — заголовок начинается с `title`
  (заголовок и подпись одним текстом).
- `koobiq.select(..., required=None)`: не нашёл поле без `*`, а с `*` оно есть — ошибка
  говорит `required=True`.
- `react_select.single/multi(..., nearby=True)`: поле по видимой подписи рядом, когда
  продукт не связал подпись с полем.
- `testence.kits.codemirror`: редактор CodeMirror 6 — `set_text`, `text`, `type`,
  `expect_text`; стенд китов получает экземпляр.
