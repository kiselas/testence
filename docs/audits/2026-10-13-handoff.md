## Отложенное: следующий бэклог

Приоритет сверху вниз. Подробности — в отчётах аудита, кратко они пересказаны в описаниях PR #31–#34.

1. **Зависания на macOS.** Дважды за 12 октября вложенный pytest упирался в 300 с, один раз задача висела 28 минут. Гипотезы агента:
   - `subprocess.run(timeout=)` в тестах не владеет деревом процессов. На Windows после kill `communicate()` ждёт без предела, пока внук держит pipe. Около 27 вызовов, один из них в замороженном `tests/test_pytest_lifecycle.py`, его не трогать.
   - `PlaywrightCdpEngine.stop()` вызывает `context.close`, `browser.close` и `pw.stop` без ограничения времени.
   
   Что делать:
   - перевести вложенные прогоны на `testence._process.run_owned`;
   - для `stop()` спроектировать убийство своего браузера и драйвера по процессу: sync API нельзя переносить в другой поток.
   
   Следующее зависание в CI уже покажет стеки.
2. **Длинные трассировки при падении.** Строка теста идёт примерно 93-й из 193; перед ней идут кадры `Actions.step` и Playwright. Нужен фильтр кадров Testence и Playwright с выключателем для отладки самого фреймворка.
3. **Безопасность, остаток из аудита:**
   - секреты в id параметров (`test_x[SECRET]`) попадают в nodeid, manifest и экспорт;
   - нет автоматического маскирования переменных окружения с «секретными» именами;
   - `fingerprints.json` хранит текст нажатого элемента;
   - строки исходника в `error_trace`;
   - CSV, XML и HTML вложения маскируются только как обычный текст.
4. **Работа с агентами, остаток:**
   - ошибки MCP `testence_click` и `testence_fill` теряют подсказку о совпадениях, которую дают шаги `ex.*`;
   - MCP не проверяет типы аргументов и не отвергает лишние ключи;
   - `plan prepare` блокирует план с `oracles: api` без блока `readiness`, а навык об этом не говорит;
   - `agent-workflow.md` обещает файлы, которых `agent install` не пишет;
   - `testence_doctor` возвращает `ok: false` без `isError`.
5. **Новый пользователь, остаток:**
   - `LoginFailed` без текста ошибки со страницы и без ARIA;
   - `doctor` молчит до 90 с, пока висит запуск браузера;
   - `TRIAGE.md` начинается с обращения к LLM.
6. **Нестабильные задачи CI.** «unexpected outcome» в Visual client simulation; бюджет по реальному времени в `bench/scale_profile --check`.
7. **Без кода, решения владельца.** Вопросы 1–5 из [обзора продукта](2026-09-28-product-review.md) открыты. P1-7 (сравнение с Playwright Test Agents) не сделан. Нет внешних пользователей и прогонов в Codex, Claude Code и OpenCode с моделью.

## Среда и правила

- **Браузер.** Встроенный Chromium на хосте разработчика не стартует. Задавать `TESTENCE_BROWSER_CHANNEL=msedge` и `TESTENCE_DEBUG_PORT=0`, для каждого pytest — новый `--basetemp`.
- **Нативные сбои CPython.** Хостовый CPython 3.12.4 изредка падает с нативным `access violation`: при старте воркера xdist, в `pathlib.stat`, при чтении `.pyc`. Это хост ([CPython #125315](https://github.com/python/cpython/issues/125315)), а не код. Повторить файл отдельно.
- **Замороженные файлы, не редактировать:**
  - `tests/test_pytest_lifecycle.py`, `test_assurance.py`, `test_evidence.py`, `test_identity.py`, `test_repair_contract.py`;
  - `bench/corpus/items.py`, `corpus/items.py`.
- **Тестовые HTTP-серверы** только через `testence.loopback.LoopbackHTTPServer`: на macOS обычный сервер тратил 35 с на обратный DNS.
- **Windows: `bash`.** На этой машине `subprocess` с `bash` запускает WSL; брать `shutil.which("bash")` и отвергать System32.
- **Git.**
  - В личном репозитории `gpgsign=false`, коммиты не переподписывать.
  - Push через `git@github-testence:kiselas/testence.git`.
  - В коммитах и описаниях PR — без `Co-Authored-By` и подписей инструмента.
  - Коммит, push и PR делать сами в логической точке; сливать только по слову владельца.
- **Проверки перед PR:**
  - `uv run ruff format --check src tests bench scripts examples`;
  - `uv run ruff check src tests bench scripts examples`;
  - `uv run mypy src scripts`;
  - полный `pytest -n 4`.
  
  Окружение как в CI: `uv sync --locked --extra dev --extra parallel --extra visual`. Простой `uv sync` убирает dev-инструменты.
